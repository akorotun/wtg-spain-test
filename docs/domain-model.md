# Accommodation API

REST API на Laravel 12 для асинхронного імпорту пропозицій житла, пошуку актуальних пропозицій та бронювання.

## Моделі

### Property

`Property` - об'єкт житла, який у системі ідентифікується за своїм code.

Один `Property` може мати кілька `Offer` від різних постачальників. Сам `Property` не належить конкретному `Supplier`.

### Offer

`Offer` - пропозиція конкретного `Supplier` для певного `Property` на конкретні дати та умови.

Для одного об'єкта можуть одночасно існувати пропозиції від різних постачальників з різною ціною та доступністю.

### available_units

`available_units` як кількість доступних одиниць конкретної пропозиції.

Наприклад:

- `max_guests = 4` - одна одиниця пропозиції розрахована максимум на 4 гостей;
- `available_units = 3` - зараз можна зробити ще 3 бронювання цієї пропозиції.

Кожне успішне бронювання зменшує `available_units` на 1.

Фізичний зміст `unit` у завданні окремо не визначений, тому в реалізації це абстрактна одиниця доступності пропозиції.

### Валюта

`currency` зберігається як трилітерний код валюти.

Конвертація валют не входить у межі завдання. 
Передбачається, що пропозиції одного `Property`, які порівнюються для визначення найдешевшої, мають однакову валюту.

### Supplier та імпорт

Постачальник визначається за значенням `supplier`, переданим у запиті імпорту.

Автентифікація постачальників не описана в завданні, тому перевіряється лише існування такого `Supplier`.

Один імпорт може містити до 50 пропозицій. 
Обмеження введене для контрольованого розміру HTTP payload та часу виконання одного queue job.
### User

Модель `User` не використовується.

Бронювання створюється без реєстрації користувача за даними клієнта, переданими безпосередньо в запиті.
